# 故障排查

记录时间、请求、受影响页面和实际构建。先区分静态资源、Rust API、数据库、存储、Agent
和模型供应商；一次请求的模型回复不能代替业务完成证据。

## 核对版本和范围

按[实际版本对照表](compatibility-and-upgrades.md#版本从哪里查)核对前端 build-info、后端产物和 Agent 进程。分享故障材料前遮蔽配置和凭据。
日志路径、服务管理及回滚命令以[部署运维](deployment-and-ops.md)和
[容器运维](../deploy/docker/README.md#运维与备份)为准，避免混用两种部署的目录。

| 现象 | 核对方式 |
| --- | --- |
| 首次安装失败 | 配置是否完整、数据库就绪、迁移/索引契约与安装日志；不反复初始化已有库 |
| 登录或后台 401/403 | 当前账号角色、冻结状态、令牌代次和服务签名；不靠聊天自述身份 |
| 文章保存冲突 | 重新读取原文与草稿，审阅差异；不覆盖其他编辑的新版本 |
| 图库列表正常但封面/裁剪失败 | 检查选中资源的实际图片请求、预览签名期限、CORS、来源与响应类型 |
| R2 不可用 | 区分图库与发布两套凭据、桶/前缀/公开来源；核对真实对象而非只看列表成功 |
| 本地图片丢失或无法写入 | UPLOAD_DIR 是否持久、运行账号权限和挂载；同时核对数据库记录 |
| 生图超时或结果未知 | 核对原任务状态与供应商结果，不盲重发付费请求；入库独立确认 |
| 聊天断流、卡片或回报异常 | 账号/会话/任务绑定、SSE 版本、代理和宿主保存结果，随后关联 Agent trace |
| 公告批准后不知道是否成功 | 查询原操作历史回执与当前业务状态，不清去重表、不换编号盲重试 |
| 后台计划未回报 | Agent Worker、有限委托和宿主来源会话结果分别核对 |
| 发布检查缺表或索引 | 核对产物对应的编号迁移；先备份、隔离验证，再按运维流程执行 |
| CI 的 rust 作业失败 | 先定位失败步骤；依赖审计拒绝未维护公告不等于编译错误，按[依赖维护](dependency-maintenance.md)核对公告与依赖链 |

## 图片加载的具体检查

浏览器 Network 中区分列表 API、缩略图、选中后的预览与裁剪资源请求。
核对失败 URL、HTTP 状态、Content-Type 和控制台的 CORS/解码错误。
签名链接按用途短期有效，不将真实链接、令牌或私有图片贴进公共 Issue。
不要把加载失败修成绕过图片访问授权，也不要因列表可读就认为裁剪请求已成功。

## 未知结果与恢复

关闭窗口、断连、请求超时和取消都不保证业务回滚。
确认、去重和历史回执是业务状态，不是可随意清掉的缓存。
历史成功也不证明资源现在仍存在。先只读核对，再决定是否准备独立的纠正操作。

备份同时覆盖 PostgreSQL、持久上传与私有配置；还原先在隔离环境演练。
只切换二进制不等于回滚数据库，见[部署与回滚](deployment-and-ops.md)。
Agent 内部排障见[Agent 文档](https://github.com/BigLeopardCat/saudade-blog-agent/blob/main/docs/troubleshooting.md)，
安全问题走 [SECURITY](../SECURITY.md)。
