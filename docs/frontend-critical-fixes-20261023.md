# 前端审计紧急修复（2026-10-23）

本轮对应 `frontend-audit-2026-10-22.md` 的 FE1、FE2、FE3。河灯重构已由 PR #38 单独合并。本轮不涉及 IoT。

## 后台写入结果

公告与分类的新增、修改、删除仅在 HTTP 200 且业务 `code=200` 时关闭表单、清理选择和报告成功。业务失败与网络失败保留输入及选择；同步锁覆盖同一帧的重复点击，等待期间禁止切换编辑目标。公告发布通知也只在确认成功后派发。分类字符串颜色可直接编辑，更新成功刷新共享分类目录。

回归使用 esbuild 加载真实页面事件处理器，以可控接口返回和状态桩驱动失败、重试与重复点击；不是浏览器端到端测试。

## 阅读与分类请求归属

文章和分类按路由资源建立独立组件实例，读请求支持 AbortSignal，并按请求通道检查当前代次。旧正文、404、统计与 loading 回调不能覆盖新资源；点赞与收藏的迟到回执同样检查归属。错误与空数据分别展示，失败可重试。分类卡片使用稳定业务 key，并限制入场延迟，避免长列表末尾等待数十秒。

## 草稿确认与离页保存

keepalive 预算按 UTF-8 字节判断，发送尝试不会推进“已保存”快照。离页请求与普通自动保存共享在途控制；发布先冻结自动保存并等待既有请求，采纳已创建草稿的 id，再执行提交。页面恢复时重试未确认内容；卸载后的尾随保存采用离开时快照，避免重新读取已销毁表单。

限制：keepalive 请求受浏览器共享 64 KiB 预算约束，60,000 字节单请求阈值仍不能保证投递。大稿、断网或硬关闭可能丢失尚未确认的最后修改。本轮没有加入 IndexedDB 恢复或后端创建幂等键；服务端已创建但响应丢失时，客户端无法保证跨重试恰好创建一次。应以后端幂等键与按账户隔离的恢复缓存继续补齐，不能把本轮修复描述为“绝不丢稿”。

## 验证

新增用例覆盖后台失败误报、可控响应乱序与取消、UTF-8 预算、未确认重试、草稿首次创建单飞及发布等待。全量前端套件、TypeScript 与 ESLint 的实际结果以 PR 验证记录为准。生产构建在 CI 执行，未在共享生产主机运行 `vite build` 或 `cargo build --release`。

本地结果：65/65 个前端套件通过，`tsc --noEmit -p tsconfig.json` 通过，ESLint 0 errors / 215 warnings；widget pin 逐字节检查通过。新增套件不是浏览器端到端测试。

## 合并后发现的 CI 阻塞

PR #38 合并后的检查 run 39815185419 在主分支新加入的待办锁测试失败：测试假定测试库已存在管理员，而 CI 只初始化表结构。修复为独立 UUID schema 中创建专属 actor，再验证两个事务确实串行；正常路径结束删除 schema，不读取或锁定业务用户。该 Rust 测试由 PR CI 的真实 PostgreSQL 验证，本机未运行 Rust 编译。

全量前端检查也发现旧 `note-visibility` 源码契约未跟随主分支提取 `public_condition()`，已同时检查调用点与共享函数体的公开、状态白名单、非修改稿三项 AND 条件。
