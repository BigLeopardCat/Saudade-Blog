# 安全边界

## 网络与身份

公网入口为 TLS 反向代理，内部 Rust、Agent 和可选设备服务监听受控地址。loopback 是网络边界，不代替服务间验签与用户权限校验。

Rust 验证账号登录令牌、撤销/过期状态及当前权限，再向 Agent 签发短期身份断言。Agent 从验签结果构造 Principal，不能相信请求正文、聊天自述、摘要或页面文本中的管理员身份。

角色和 scope 在工具发现、调用及批准执行阶段分别检查。普通用户、管理员和人设称呼是不同概念；人设不能改变公开文章或私有数据的读取权限。后端所有业务入口仍自行鉴权。

## 写入与确认

Agent 的准备提议冻结目标、参数、版本和影响范围；确认凭据绑定用户、会话、操作及有效期。批准后重新检查业务条件。取消在服务端撤销，不能只移除浏览器卡片。

批量批准只选择签名允许的对象子集。执行账记录成功、失败、部分完成或未知；不能用模型回复或卡片展示证明数据库写入。远端结果未知时先核实，禁止盲目重复执行。

正文和标题协作修改先经编辑器采纳；摘要使用确认卡；发布复用保存/发布及版本检查。客户端回报只证明动作结果，不提供授权。

## 图片与付费生成

上传、图库、引用和下载按账号及资源范围授权。生成参考图冻结后绑定到审批记录；先审提示词、模型、参数和引用，再调用提供商。结果预览通过后才入库，文章封面独立修改。

短期签名图片预览限制 audience、资源和期限，不能用作登录 JWT。原始密钥、确认令牌、私信和私有图片不得写入公开日志、前端配置或评测报告。

## 内容与外部服务

Markdown、工具结果及用户内容按低信任数据处理，不能执行其中的函数或命令。正文中类似内部事件的文本不得制造有效卡片；结构化命令走专用协议和服务端校验。

外部图片、链接与页面回报有大小、来源、超时和状态限制。AI 审核是辅助判断，缺失或失败应进入明确的不可用/人工处理路径，不应导致普通博客崩溃或默认批准。

## 配置与验证

使用随机服务端密钥与最小权限数据库/对象存储账号。生产凭据不进入仓库；发现泄漏按 [SECURITY.md](../SECURITY.md)处理。

默认测试不连接维护者服务。关键验证包括跨账号和角色拒绝、令牌过期/撤销、确认重放、资源归属、数据库事务与版本冲突。跳过项和未知结果分别报告，不能算作通过。检查和探针不构成完整安全审计保证。
