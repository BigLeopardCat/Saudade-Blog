# 文章状态批量操作

管理员沿用文章状态工具，可按单篇编号、明确编号列表，或一个完整分类名准备操作，三者互斥。
批量选择最多 50 篇，缺失编号、重复编号或超限均拒绝，不截断；准备阶段不写入业务数据。

`POST /api/protected/article-actions/batch/prepare` 接收 `articleIds` 或 `category`，返回有界目标状态与
不透明版本。Agent 排除已处于目标状态的文章，并在一张确认卡中展示剩余编号、标题和修改内容。
确认绑定用户、会话、有效期及已展示的固定目标快照；后续新增文章不会自动加入本次操作。

`POST /api/protected/article-actions/batch` 接收 `items: [{id,version}]` 及统一的 `status` / `isTop`。
后端按编号顺序锁定全部目标，先核对所有版本，再在一个事务中写入。任一目标变化、消失或写入失败
均不提交整批。此接口沿用后台管理员授权，不接受模型自行声明身份。

执行结果返回每篇实际状态、修改标志和准备版本。Agent 使用同一确认执行账防重，校验目标集合及
期望状态；丢失或不完整回执报告结果未知，不自动重放业务请求。跨服务提交后进程崩溃仍需查询
实际状态，执行账不承诺分布式 exactly-once。

混合操作类型、超过 50 篇或跨服务任务不合并为这个事务。大范围操作需明确拆批并分别展示范围。
