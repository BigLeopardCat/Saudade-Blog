# 聊天持久化与上下文职责

登录用户的 `/api/chat/stream` 使用标准 SSE 具名事件。`text` 逐步显示，`done` 表示上游成功结束，且本轮回复、执行回执和待确认状态保存成功。访客不创建聊天记录。非流式接口在相同保存条件满足后返回成功。

## 保存与失败

- 回执到达后立即保存；同批回执和待办更新使用一个短事务，失败整批回滚。
- 收到上游 `done` 后保存完整助手正文，成功后才向浏览器转发 `done`。
- 上游错误、非法协议或提前断流不把残缺正文保存为完整消息；已提交回执保留。
- 写入使用 Tokio task。浏览器断开只取消等待方，已开始的短写入继续完成并记录带 trace ID 的失败。

本地展示副本保存失败不能证明远端业务失败。服务不自动重做业务写入；Agent 的持久执行账处理幂等和未知结果。这不构成跨服务 exactly-once。

## 记忆归属

Agent 的 LangGraph checkpoint 管理活动上下文、框架摘要和执行恢复。博客只保存原始聊天记录、回执和待确认展示状态，不调度或写回模型摘要，也不因摘要成功而删除聊天原文。

`chat_context::load_bootstrap` 提供最近 20 条同来源历史，仅在 Agent 首次初始化时导入。每条记录的 `source_role` 在请求时由数据库核实；导入必须匹配用户、会话和当前角色。来源未知的旧记录可在历史页面查看，不按当前角色补造来源。

已有 `chat_summary` 作为归档保留：只读入来源匹配且覆盖边界有效的摘要。它可能是已经清理原文的唯一资料，因此不删除此表。新请求不再发送摘要批次或接受摘要写回，也不维护覆盖水位的并发写入协议。

丢弃轮次在一个短事务中删除指定范围的原文，并使覆盖该范围的归档摘要失效；失败整批回滚。用户删除与 Agent 的删除屏障保持独立协调，摘要不能重新导入已经删除的会话。

## 接口

`POST /api/chat/task/confirmation` 读取当前待确认卡，要求登录和本人会话；可选
`task_id` 用于拒绝其他任务的结果。宿主从数据库读取当前角色签名断言，转发到
Agent `/tasks/confirmation` 并返回 `Cache-Control: no-store`。此查询不调用模型、
不执行或重签操作，也不将凭据写入聊天历史。确认是否仍有效以 Agent checkpoint
与签名授权状态为准；宿主 `pending_action` 是展示与审计副本。

卡片的操作身份独立于回复正文。旧卡收尾仅更新其来源消息，重载与跨标签页恢复不从
本地缓存读取确认凭据；历史消息未加载时，当前有效卡单独展示。发布本接口时同步
`widget.lock.json`，使查询适配和对话组件随同一博客版本上线，无新增数据库迁移。


新装仍需应用来源列迁移 `scripts/migration/pg/0018_chat_memory_source_role.sql`。迁移不回填未知来源。

## 验证

MockDatabase 覆盖插入失败、回执回滚、只读导入和 SSE 终止顺序；Tokio 测试覆盖等待方取消后的写入；PostgreSQL 测试覆盖真实回滚、回执保留和归档失效。测试使用随机会话及回滚夹具，不依赖生产账号或真实模型。
