# 聊天完成与持久化

登录用户的 `/api/chat/stream` 保持标准 SSE 具名事件协议：`text` 可逐步显示，`done`
表示上游成功结束，且本轮已收到的回复、执行回执和待确认状态保存成功。访客不创建聊天记录。
非流式接口在相同保存条件满足后返回 `success: true`。

## 保存顺序

- `receipts` 到达时立即保存。一个回执批次及其待办状态更新使用同一短事务，失败则整批回滚。
- 收到上游 `done` 后保存完整助手正文，成功后才向浏览器转发 `done`。
- 收到上游 `error`、格式错误或提前断流时，不将残缺正文保存成完整助手消息。
  已经提交的执行回执保留，不能因回答失败而撤销已发生的业务事实。
- 摘要是派生缓存，按来源和预期旧值做条件更新。保存失败或并发冲突保留当前摘要，
  不撤销已保存的完整回复；没有成功更新时不触发历史清理。

## 取消与失败

`chat::persistence` 使用 Tokio task 执行短写入，正常请求等待该任务完成并检查结果。
浏览器在写入期间断开时，只取消 HTTP 等待方，已开始的写入继续完成；任务自身记录带 trace ID
的失败。数据库或任务错误不会变成 `done`，也不向浏览器暴露数据库异常原文。

本地聊天记录的保存失败不能证明远端操作失败。界面提示用户先核对结果、避免重复执行，
服务不自动重试写入。Python 的持久执行账仍负责业务操作的幂等与未知结果处理；博客记录是
展示与检索副本。这不构成跨服务 exactly-once，也不保证进程崩溃后恢复尚未提交的副本写入。

## 回归范围

- MockDatabase 验证回复插入失败、回执批次回滚及 SSE 终止事件。
- Tokio 通道验证等待顺序和等待方取消后写任务继续执行。
- CI 的 PostgreSQL 服务验证真实事务回滚，以及回复失败不丢失已提交回执。
- 无需真实模型、生产账号或生产数据库。

## 长期记忆与来源

执行状态由 Agent 的 LangGraph checkpointer 持久化；这里的聊天历史与滚动摘要是独立的
导入上下文和展示记录，不承担工具执行恢复或授权。

新写入的用户消息和助手回复都记录请求开始时经数据库核实的 `source_role`。导入 Agent
的历史、摘要必须同时匹配用户、会话和当前角色，分别附带 `history_scope`、`summary_scope`。
未知角色或来源为空的旧记录仍可在本人历史界面查看，但不作为模型上下文；不能按账号当前
角色回填历史来源。更换角色时，其他来源的摘要内容及覆盖水位均不复用。

### 增量摘要协议

- 主任务上下文读取最近 20 条同来源消息，排除本轮新插入的用户消息。
- 摘要独立读取保存水位之后**最早**的完整前缀；至少 10 条、每批最多 60 条，保留完整正文。
  批次正文合计目标上限为 12,000 字符，超出时缩小完整前缀；首条自身超长则完整交给 Agent
  判断预算，不截字后登记覆盖。消息 ID 只需严格递增，跨会话产生的全局 ID 空洞不表示本会话漏读。中断的旧用户消息也可
  被总结；本轮尚未完成的消息不进入该批次。
- 发送 `summary_batch: {base_id, messages:[{id,role,content}]}`，Agent 在主任务成功后用剩余额度
  尝试总结；预算不足可以不返回摘要，水位保持原值。
- HTTP 读取 `new_summary` 与 `summary_coverage: {base_id,through_id}`；SSE 的私有 `summary`
  事件读取 `{text,base_id,through_id}`。它们不转发给浏览器。
- 接受更新时必须匹配本次实际提供的两个边界，以及读取时的旧来源、水位和摘要正文。
  首次保存使用 `ON CONFLICT DO NOTHING`；已有摘要使用 compare-and-swap，竞争失败需下轮重读。
  `lock_version` 随摘要更新和丢弃轮次递增，阻止删除期间仍在途的摘要把旧内容重新保存。
  丢弃轮次在短事务中删除历史并使相关摘要失效；无摘要时写入空占位，也阻止首次摘要迟到插入。
  旧字符串摘要、缺覆盖范围、边界不符、空或过长摘要均不推进水位，也不影响主回复。
- `CHAT_HISTORY_LIMIT`（默认 500）是保留目标。只删除已被**同来源**摘要覆盖的旧消息，
  未覆盖及来源未知的记录即使超出目标也保留，避免清理速度超过总结速度。
- 确认执行请求不插入虚构用户消息，也不调度摘要。

### 部署顺序

先以业务表所有者应用 `scripts/migration/pg/0018_chat_memory_source_role.sql`，再部署读取新列的
后端。迁移可重复应用，不补造旧来源；CI 新装清单已登记此迁移。生产部署脚本目前不自动
运行 PostgreSQL 迁移，不能跳过此前置步骤。回退应用时保留新增可空列，旧版可以忽略它们。

回归覆盖完整积压前缀、长消息尾部、角色隔离、错误摘要不影响回复、并发 CAS 与按来源清理；
PostgreSQL 验证使用临时数据库和回滚夹具，不调用模型或执行业务操作。
