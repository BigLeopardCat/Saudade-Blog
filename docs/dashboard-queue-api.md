# 后台队列读取

两个 GET 接口仍由后台管理员守卫鉴权；Agent 使用发起人身份调用。

| 接口 | 筛选 | 排序 |
| --- | --- | --- |
| `/api/protected/quota/requests` | `status=pending/approved/rejected/all`、正整数 `id` | 申请编号降序 |
| `/api/protected/todos` | 可选 `done=true/false` | 当前用户的 `sort_order,id` 升序 |

传入 `page_size=1..50` 启用分页，`page=1..10000` 默认 1。只传 page、越界参数或未知状态会失败。
分页响应沿用 `ApiResponsePage`：`data` 是本页数组，`total` 是同一筛选下的数据库总数。
数据库计数或记录读取失败时返回错误，不返回空数组。计数和列表是相邻查询，未提供跨请求快照。

不传分页参数保留已有页面和写后复核契约：额度列表最多 200 行，待办返回当前用户列表；不附 total。
待办保存的响应仍使用原有 ApiResponse，不修改保存或单条变更语义。

额度条目新增 `accountExists`。账号缺失与账号元数据查询失败不同：前者保留申请并标识 false，后者整次读取失败。
旧字段 used/limit 在账号缺失时仍保留兼容零值；消费方必须先核对 accountExists，不能据此判断用量或不限额。
元数据查询仅选择当前页账号所需字段，不读取密码列。

原生 Agent 每页默认 5 行、最多 10 行：额度列表只带理由/备注节选；按编号读取详情时，分别最多 500/255 字并标记截断。
待办读取只提供个人日程，不附加系统审核队列计数。所有读取均不修改业务数据。
